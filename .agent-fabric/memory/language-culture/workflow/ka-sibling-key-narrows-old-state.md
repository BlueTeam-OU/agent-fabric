## a key for a new state narrows the old one: drop from the old key's Georgian text the cause that now belongs to the new one

When a surface splits one state in two (a new key takes one case), the old key's ka-GE text that named that case becomes wrong while the validator stays green. Rewrite the old one on the same branch, without the cause, true for every remaining cause. Source: gzapp j114/j115, admin.step-up.failed, b37e530e0. The same holds when a key splits into a variant or its fact changes, and the affected value is not found by prefix: the shared title journey.wake.alighting.title did not fit the new on-request body (the cold read showed it; title-on-request was added, 01a15622 → 01a15623); and when ADR-077 was revised, the bodies dropped the "on request only" claim while the in-app hints journey.now.on-request-* still made it, which language-culture-en caught, not I (01a157d7). On every new or changed key, search the whole ka-GE dictionary for values that state the same fact (sibling states, a variant's shared title, another surface's hints) and ask which is no longer true.
