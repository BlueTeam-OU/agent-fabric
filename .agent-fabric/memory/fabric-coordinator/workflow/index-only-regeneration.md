## How to regenerate a project's drifted .agent-fabric/memory/<role>/INDEX.md with no drain, and what to revert after

A project INDEX.md that misses fabric domain slices (corpus lint "does not list … the index has drifted") is regenerated by an index-only assemble run. `tools/fabric/assemble.py` has no index flag and refuses without `--claims` and `--drain`, and it reads `references.json` and `observations.jsonl` from the drain. So pass an empty claims directory and a drain directory holding `{}` and an empty file: `--claims E --drain D --project X --fabric <fabric main> --working-copy <wc> --stamp <today>`. Every held role is re-indexed, and a role the taxonomy binds whose domain has slices gets a new index (gzapp ux-designer, 2026-10-30).

The run also rewrites `last-drain-report.json` (a drain that did not happen), every `crossref.json` (`generated_at` only) and every INDEX `distilled_at`. Keep only the INDEX.md files with content changes, plus new role directories, and revert the rest.

Two more checks before you trust a lint result:
- Lint the sibling repositories at `origin`, never the local checkouts. The sibling checkouts beside the fabric can be stale (InterWeave was 1544 commits behind), and then the lint reports drift that `origin` has already fixed. Use detached worktrees at `origin/HEAD` and `lint.py --no-siblings --working-copy X=<dir>`.
- The commit happens in the project's own repository, so it is a job of that project and needs its own session. The one-job guard refuses a commit outside the job's working copy ([[guard-counts-session-cwd]]). j442 was filed against agent-fabric and became j482 (herdr) and j483 (gateway).

Outcome (2026-10-31): fleetdeck #53 and gateway #76 merged; the lint against all three repos at origin then reported no index findings. InterWeave never needed a PR, because its drift existed only in the stale local checkout. Its 10 over-budget slices are j484.
