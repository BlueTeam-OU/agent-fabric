# 2026-09-29 — Claude Sonnet 5.5 on the anthropic path, read back

The owner asked for `code-low` and `code-medium` to move to Sonnet 5.5 on
every agent. The model postdates this coordinator's training data, so
its id was not known and was measured, the way Opus 5.5's was
(`2026-09-23-opus-5-5.md`). The probes ran on develop-qzapp as user,
with plain `claude -p --output-format json`, at `--effort medium`, which
is the level both classes ask for.

## The id

| `--model` | init model | `is_error` | `modelUsage` | cost (USD) |
|---|---|---|---|---|
| `claude-sonnet-5-5` | `claude-sonnet-5-5` | false | `claude-sonnet-5-5` | 0.084 |
| `claude-sonnet-5.5` | `claude-sonnet-5.5` | true | none | 0 |
| `claude-sonnet-9-9-not-a-model` (control) | the same | true | none | 0 |

The refused two answered "There's an issue with the selected model … It
may not exist or you may not have access to it". The control shows that
the first row is the model answering, not a silent fallback. The
served session also named `claude-sonnet-5-5` itself when asked.

## Through the aliases

The launcher does not pass a class's model on `--model`. It exports it
for the class's tier alias (`runtime/claude-code/aliases.json`:
`code-low` rides `haiku`, `code-medium` rides `sonnet`), and a subagent
names only the alias. With `ANTHROPIC_DEFAULT_HAIKU_MODEL` and
`ANTHROPIC_DEFAULT_SONNET_MODEL` both set to `claude-sonnet-5-5`:

- `--model sonnet`: init model `claude-sonnet-5-5`, `is_error` false,
  `modelUsage` only `claude-sonnet-5-5`.
- `--model haiku`: the same.

## Effort

`medium` was accepted on every served probe. `tools/fabric/routing.py`
places `claude-sonnet-5-5` under its catch-all row `claude-*`, which
admits low to max, so the routing check has nothing to write down.
Whether medium is also Sonnet 5.5's own default was not measured. It
matters only for a session started without the fabric's effort, which
the launcher never does.

## What the harness reports as its cost

Anthropic publishes Sonnet 5.5 at $2 per million input tokens, $10
output and $0.20 cache read, and Opus 5.5 at $4 and $20, with the same
$0.20 cache read (platform.claude.com/docs/en/about-claude/pricing, read
2026-09-29). Two prompts were run on each model at medium, one short
("Reply with the single word: ok") and one long (400 words), and the
harness's `modelUsage` was recorded:

| model, prompt | input | output | cache read | cache write | `costUSD` |
|---|---|---|---|---|---|
| Opus 5.5, short | 2 | 4 | 10118 | 7596 | 0.0628796 |
| Opus 5.5, long | 6 | 2756 | 51190 | 9701 | 0.14299 |
| Sonnet 5.5, short | 2 | 4 | 23945 | 4683 | 0.042341 |
| Sonnet 5.5, long | 2 | 794 | 23945 | 4694 | 0.058229 |

- **Opus 5.5.** Both rows reconstruct at $4 input, $20 output, $0.20
  cache read and $8 cache write (twice input: the one-hour cache rate).
  For example, the long row: 6×4 + 2756×20 + 51190×0.2 + 9701×8 per
  million is $0.14299.
- **Sonnet 5.5.** Both rows reconstruct at $20 output and $8 cache write,
  not the published $10 and $4. The long row: 794×20 + 23945×0.2 +
  4694×8 (+ input) per million is $0.05823. At $10 and $4 it would be
  $0.0315. The input rate separates too, even at 2 tokens: the short row
  is 2×4 + 4×20 + 23945×0.2 + 4683×8 per million, $0.042341 exactly,
  where $2 input would give $0.042337. Every rate is Opus 5.5's.

So Claude Code 2.1.282, the pinned harness, reports Sonnet 5.5 at all
of Opus 5.5's rates: input, output, cache read and cache write. Why is a hypothesis, not measured:
most likely its price table has no row for a model newer than the
release. The model runs as itself (`modelUsage` names only
`claude-sonnet-5-5`). Only the dollar figures the harness reports for
code-low and code-medium read about twice the real cost. Re-run these
four probes after a harness upgrade to see whether that has changed.

## What it decides

In the anthropic column of `routing/capabilities.json`, `code-low` and
`code-medium` are `claude-sonnet-5-5`. `code-high`, `code-plan`, the
review class and the session stay `claude-opus-5-5`, and the broker
column is unchanged. `runtime/openrouter/launch --print --provider
anthropic` then exports `claude-sonnet-5-5` for both the haiku and the
sonnet alias, each at effort medium. No login's local layer overrides
either class; this was read on every placed account before the change.
The change reaches each agent at its next launch after distribution.
