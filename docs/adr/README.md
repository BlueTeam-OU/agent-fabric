# agent-fabric decision records

What agent-fabric has decided, why, and since when. **Read
[DIGEST.md](DIGEST.md) first**: what is true now, one entry per record,
with the rules and their section numbers. Open a record for the reasons,
the alternatives and the exact wording; where the DIGEST and a record
disagree, the record wins.

Every record serves the purpose stated in
[ADR-000](ADR-000-the-enduring-organization.md) — infrastructure through
which people and agents build enduring organizations — and names one of
its pillars.

## When a record is required

A decision needs a record when it:

- changes what an agent is, what a role may do, or how authority flows;
- changes how models, effort or providers are chosen;
- adds, changes or retires a fleet operation, a guard or a protocol rule;
- changes where knowledge lives or how it is curated;
- commits the fabric to a direction (a pillar's "Direction").

A fix that restores what a record already says needs none; a fix that
changes what it says is an amendment.

## Lifecycle

| Status | Meaning |
|---|---|
| Proposed | Drafted; not binding |
| Accepted | Binding from its `Ratified:` date; the line names where the owner's word is |
| Superseded (→ ADR-NNN) | Replaced; the body is frozen and carries a point map to where each rule now lives |
| Deprecated | No longer applies and replaced by nothing |

## Changing a record

- **Amend** when the decision stands and its details move:
  `tools/fabric/adr.py amend NNN "title" --date YYYY-MM-DD` writes the
  history note stub and the table row; edit §1–§8 in place (a withdrawn
  rule becomes a tombstone, a changed one carries `(A YYYY-MM-DD)`), fill
  the note, add the `A YYYY-MM-DD` bullet to the DIGEST entry, and put the
  reasons in the commit body.
- **Supersede** when the decision itself is re-made: a new record; the old
  one's status becomes `Superseded (→ ADR-NNN)` and it gains a point map.
- **Editorial** fixes (a typo, a renumbered citation) carry an
  `ADR-Editorial: <why>` trailer on the commit instead of an amendment.
- **New**: `tools/fabric/adr.py new <slug> "<title>"` takes the next
  number from [ADR-TEMPLATE.md](ADR-TEMPLATE.md).

Then `tools/fabric/adr.py index --write` regenerates the index below and
`index.json`; `tools/fabric/adr.py check` must be clean. Both run in CI,
in the commit hook and in `tests/run.sh`.

## Who writes, who accepts

fabric-coordinator writes; the owner accepts. Any other role proposes — a
GZCoord REQUEST to the coordinator, or a `rationale` slice in its own
memory. The rules are [ADR-001](ADR-001-decision-records.md) §5.

## Reading by pillar

The pillars are ADR-000 §5's table. Read a pillar's records in number
order; the DIGEST's keyword table finds a record by subject.
