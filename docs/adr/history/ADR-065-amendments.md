# ADR-065 — amendments

The full notes; the ADR's body reads current and its Amendments table lists them.

### Amendment 2026-10-31 — A full review carries the findings earlier chains left open

#425 merged with F5 open. An earlier review chain raised it, nothing judged it, and a fresh full review of the head started a chain of its own, which the review gate read as "head reviewed". Gate 4c of `fabric-pr arm` now refuses on a finding open in any chain (`tools/fabric/github/arm_findings.py`, #437). That closes the merge, but the next full review still did not know the finding existed, so the PR could only be armed by a re-review on the old chain or a `--defer`.

A PR's full-review brief now reads the PR's reviews with the same reader and from the same accounts (the PR's author and `AGENT_FABRIC_REVIEW_POSTERS`), and lists each open finding with its label, level, place and the head it was raised on, for the reviewer to answer in a `Judgement:` line. The reviewer numbers its own findings past every label the PR's reviews used, closed ones included. A judgement goes to its own chain whenever that chain raised the label, so a new F5 would take the judgement meant for the old one. A finding raised on the head under review is another engine's same round, and blind review (ADR-020) keeps it out; its label still counts. Reviews that cannot be listed refuse the render, and so does a listed review that cannot be read (no body, no machine lines, a malformed line), since rendering either as none is the gap this closes: its open findings would go uncarried and its labels reused (#437 round 3, F6). The Codex engine is handed none: its answer carries findings only and its renderer numbers them from F1, which a follow-up of its own changes.

### Amendment 2026-11-01 — A coverage block may carry a default entry

A memory drain's range is a thousand paths, and a block naming each one was 148KB against the 60000 characters a block may hold, so its review could not be posted at all (#447). A block may now carry an optional top-level `"default": {"status", "reason"}`, the entry of every path of the range the block does not name. It is a key of its own, not a path called `*`, since a file may be called that. A path the block names keeps its own entry whatever the default says, and a path named outside the range is still refused, so the default never widens what a review may claim. A `not read` default makes the review partial, and the line after the marker says so: the block alone cannot show that no path falls under it, so it is never counted as coverage of the head. A block without a default reads and posts as before. The Codex engine builds its block from its answer schema's per-path arrays and does not yet emit a default.
