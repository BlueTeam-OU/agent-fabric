### Amendment 2026-10-17 — Accepted; the digest check is per file; sizes restated

The owner accepted the record in the coordinator's session ("adr 060 accepted", 2026-10-17). With it, round 2 of #289's blind review (review 5556925209) found four wordings that no longer matched: §5 rule 3 said each install records the digests of the files it installs, which leaves no digest for a file an earlier install wrote, so a later install that touches one file would refuse a launch for the other; it now says the record of an install is its signed commit's tree: the launcher renders the files of the last parent-signed commit on the directory, each blob checked against its object name, which is HEAD's tree on that path, so an edit committed after the install is the last commit and refuses (#290 round 1, F3, found the code keeps no per-file digests and needs none). §4 names that check. §1's legal-expert size was measured before #289's last brief change (24 714 at 98f0c746); it reads about 24 700. §8 now says the amendments to ADR-002, ADR-038 and ADR-042 land with the mechanism, and those to ADR-018, ADR-027 and ADR-057 with rule 8's stage, where that behaviour changes.

### Amendment 2026-10-18 — ADR-057 needs no amendment; what `lang` names

§8 listed ADR-057 §5 rule 5 among the amendments rule 8's stage implies: a locale signer named by the holder's locale rather than only the login's suffix. Making that change showed it cannot hold. The signature checker runs in CI and in every managed project from public data alone: the keys, the lineage, `policies/authority.json`'s holders and the committed locale directories. A holder's `holder.json` is in its private store, which neither CI nor another account can read. A commit's signer therefore stays judged by its login's suffix or its committed holding, as before, and the locale `holder.json` names governs only what the holder's own session renders. The stage's other amendments, ADR-018 §5 rule 5 and ADR-027 §5 rules 1, 6, 9 and 13, are made the same day.

The same day, §5 rule 6 says what an addendum's `lang` is, and so whose passes rule 9 wants. python-dev-04 found the gate it built (#290 round 2) asked for `language-culture-<lang>`, which holds only when the language and the fabric's locale key are spelt alike: they are not for Georgian, whose locale key is `ge` and whose language is `ka`. The installed Georgian addenda (2026-10-17) say `lang: ka` and were reviewed by `language-culture-ge`. `lang` stays the BCP-47 language, as the holder wrote it; the reviewer is the holder of the locale whose `locale.json` tag has that language.

### Amendment 2026-10-18 — The last commit on the path, over the whole history

python-dev-01's review of the tree check (80fc4802) reproduced a rollback: an agent can commit a merge whose parents are HEAD and an older parent-signed install, carrying that install's directory. `git log -1 -- <path>` simplifies history along the parent that matches, names the old install, and its signature and tree pass, so an earlier text renders under the parent's signature. Rule 3's "last commit that touched" the directory is now judged over the whole history: each commit's answer is computed from its parents' answers, and a merge whose version of the directory is not a three-way carry-over of one parent's is itself the change, which an agent-signed merge fails. The refusal names the commit and says it is a merge. A shallow store is refused like grafts, since it cuts the history the walk reads. The newest-parent-signed alternative was rejected: "newest" needs an order the agent controls. It remains a fence, not a wall (§6).
